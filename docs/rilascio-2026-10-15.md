# Rilascio 15 ottobre 2026 — Giacenze nella pagina prezzi

Versioni: backend gestione-ordini-api **6.2.12**, frontend **5.2.13**.
Branch: backend prod, frontend master.
Versioni precedenti: backend 6.2.11, frontend 5.2.12.

## Contenuto

- Ricerca, anteprima e aggiornamento prezzi limitati ad articoli con giacenza
  totale strettamente positiva, sommata da SALDIMAGAZZINO su tutti i
  magazzini/varianti per la quantità principale QTY='1'. La quantità
  secondaria QTY='2' non è sommata alla principale.
- Colonne Magazzino e Giacenza: mostrano soltanto i magazzini con saldo
  positivo, nella stessa riga dell'articolo; nessuna duplicazione della
  selezione o dell'aggiornamento del prezzo.
- Prima gli articoli aggiornabili, poi gli altri esclusi, infine gli articoli
  senza costo valido. Ordinamento conservato dopo annullamento anteprima.
- Saldi riletti con HOLDLOCK in aggiornamento. Se il totale non è più
  positivo al salvataggio, conflitto 409 prima di qualsiasi scrittura prezzi.

Il filtro sul totale comprende anche gli eventuali saldi negativi, benché
non visualizzati. Dettagli: [Articoli e prezzi](articoli-classificazioni-e-prezzi.md).

Il restyling dashboard non è incluso: è conservato negli stash nominati
`feature/restyling-dashboard: pausa prima filtro giacenza prezzi` dei due
repository. Non applicarli ai branch principali durante questo rilascio.

## Installazione

Non occorrono script di migrazione né modifiche ai permessi. Il file
`scripts/verifica_giacenze_per_magazzino.sql` è solo una query diagnostica di
lettura, non un prerequisito del deploy. Restano validi tabella soglie e
permesso prezzi_articoli.view installati con il rilascio precedente.

1. Conservare i tag/digest delle immagini attualmente installate.
2. Scaricare da Docker Hub le immagini pubblicate pconvertini/gestione-ordini-api:6.2.12
   e pconvertini/gestione-ordini:5.2.13 (disponibili anche come latest).
3. Aggiornare insieme API principale e frontend: il nuovo frontend usa
   giacenze/giacenzaTotale restituiti dal nuovo backend. Authentication,
   API Ceglie e API Ostuni non richiedono un aggiornamento.
4. Verificare ricerca fornitori, magazzini con saldo positivo, assenza di
   righe duplicate, anteprima e ordinamento degli articoli senza applicare
   variazioni ai prezzi di produzione durante il controllo.

## Rollback

Ripristinare insieme backend 6.2.11 e frontend 5.2.12 (o i digest effettivamente
installati prima del rilascio). Nessuna migrazione da annullare. Il rollback
del software non ripristina eventuali prezzi applicati dagli utenti.

```sh

npm run build -- --configuration=production
```
