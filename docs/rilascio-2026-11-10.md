## Contenuto

- Creazione, modifica ed eliminazione di consegne indipendenti dagli ordini ERP,
  con intestazione libera o scelta dall'anagrafica clienti esistente.
- Destinazione modificabile e autocomplete località dalla tabella comuni TTCO.
  Una modifica a indirizzo/località azzera le coordinate precedenti.
- Inserimento nel planner settimanale, giri misti con ordini, drag-and-drop,
  mappa, riordino percorso, aggiornamento coordinate e condivisione WhatsApp.
- Pulsante di creazione bianco con bordo nel colore primario a destra,
  titolo centrato e icona con tooltip per le consegne senza ordine.
- Riordino trasferito da JasperService a GiroConsegneService; endpoint e
  transazione invariati. Lo stesso servizio gestisce le posizioni dei giri misti.
- Ricerca clienti e ricerca comuni disponibili anche ai ruoli Logistica,
  Amministrativo e Magazziniere. Nessun nuovo codice permesso da inserire.

Dettagli: [Consegne senza ordine](consegne-senza-ordine.md).
La lista operativa logistica degli ordini resta dedicata agli ordini;
le consegne indipendenti sono gestite dal planner settimanale.
Con filtro venditore le consegne indipendenti sono escluse.
Restyling e altri lavori negli stash non sono inclusi; documentazione e query
locali sui conti acquisti/giacenze non entrano nelle immagini runtime.

## Installazione in produzione

1. Conservare i tag/digest attualmente installati e seguire la procedura di
   backup del database prevista in produzione.
2. **Prima di avviare la nuova API**, eseguire nel database aziendale della
   API principale [create_GO_CONSEGNA_LIBERA.sql](../scripts/create_GO_CONSEGNA_LIBERA.sql).
   Lo script SQL Server è transazionale e rieseguibile: crea la tabella autonoma
   `GO_CONSEGNA_LIBERA`, i vincoli e l'indice del giro. Nessuna modifica a
   `GO_ORD_VEICOLO`, agli ordini ERP o all'anagrafica clienti.
3. Aggiornare insieme API principale 6.2.14 e frontend 5.2.15, quindi verificare
   creazione, modifica, eliminazione e riordino di un giro misto nel planner.

Authentication, API Ceglie e API Ostuni non richiedono aggiornamenti.
Il frontend richiede la nuova API per le consegne libere e i ruoli di ricerca.
Deploy e script SQL di produzione **non eseguiti** durante questa preparazione.
