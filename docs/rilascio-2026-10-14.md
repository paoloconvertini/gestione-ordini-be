  ricerca e anteprima, selezione tra pagine, aggiornamento prezzi a tre
  decimali, secondo ricarico sui deselezionati, soglia indipendente per A1,
  delta/badge e azione Porta a soglia.
- Rettifica del costo di riferimento +40% per il movimento del 31/12/2021;
  il costo originale non viene riscritto. Controlli di snapshot e transazione
  prima dell'applicazione dei prezzi.
- Menu, route e API protetti da `prezzi_articoli.view`.

Dettagli funzionali: [Articoli e prezzi](articoli-classificazioni-e-prezzi.md).

## Sequenza di installazione

1. Conservare i riferimenti delle immagini attualmente installate e un backup
   dei database aziendale SQL Server e MySQL auth.
2. Eseguire nel database aziendale SQL Server usato dalla API principale:
   - `scripts/ALTER_GO_APPUNTAMENTO_PARTECIPANTI.sql`;
   - `scripts/create_GO_RICARICO_FORNITORE.sql`.
   Non eseguirli nel datasource common/legacy né nel database auth.
3. Eseguire `scripts/permesso_prezzi_articoli.sql` in MySQL auth. Assegna
   inizialmente il permesso ad Admin e Amministrativo. Richiede nuovo login.
4. Installare API 6.2.11 e frontend 5.2.12 nella stessa finestra di rilascio.
   Le API prezzi restituiscono `{articoli, ricaricoImpostato}`: frontend e
   backend devono essere coerenti. Non occorre aggiornare i servizi
   authentication, Ceglie o Ostuni per queste modifiche.
5. Eseguire i controlli sotto prima di considerare concluso il rilascio.

Gli script sono rieseguibili e non applicano aggiornamenti ai prezzi.
La tabella soglie parte senza valori preimpostati; le soglie sono salvate
solo con l'azione esplicita dell'utente.

## Controlli dopo il rilascio

- Nuovo login Admin/Amministrativo: menu Prezzi articoli presente e ricerca
  per A1 funzionante. Utente senza permesso: pagina/API non accessibili.
- Verificare ricerca, costo rettificato, soglia e anteprima senza applicare
  variazioni ai prezzi di produzione durante il controllo.
- Verificare formazione con soli venditori, soli nomi e partecipanti misti:
  salvare, riaprire, controllare nomi in agenda e descrizione Outlook.
- Verificare che appuntamenti/visite e icone assenze funzionino come prima.
- Controllare i log API per errori SQL sulle nuove colonne/tabelle e per
  errori di sincronizzazione Outlook.

## Rollback

Ripristinare insieme le immagini precedenti di API e frontend effettivamente
installate prima del rilascio. Le aggiunte SQL sono compatibili con il codice
precedente: conservarle, senza eliminare i partecipanti e le soglie salvati.
I vecchi programmi non mostrano i nomi liberi.
Il rollback del software non ripristina prezzi eventualmente applicati dagli
utenti: per quelli serve il backup o un ripristino dati concordato. La nuova
funzionalità non conserva uno storico completo dei prezzi precedenti.

## Build riproducibile senza pubblicazione

Dalla root backend:

```sh
scripts/run-with-env.sh mvn -pl gestione-ordini-api -Dquarkus.http.test-port=0 -Dtest=AppuntamentoServiceTest,PrezziArticoliServiceTest,PrezziArticoliResourceTest test
scripts/run-with-env.sh mvn -pl gestione-ordini-api -DskipTests -Dquarkus.container-image.build=false -Dquarkus.container-image.push=false package
```

Il pacchetto JVM eseguibile è l'intera directory `target/quarkus-app`, non
il solo JAR. Per costruire l'immagine API dal pacchetto verificato usare il
Dockerfile JVM del modulo con tag 6.2.11. Non usare `build-versioned.sh`
per ricostruire questa versione: lo script incrementa di nuovo la patch.

Dalla root frontend:

```sh
npm run build -- --configuration=production
```

Artefatto statico: `dist/gestione-ordini`, versione package 5.2.12.
Il Dockerfile frontend esistente ricostruisce con npm ci e la configurazione
production. Non vengono cambiate configurazioni Nginx o servizi ospitanti.
